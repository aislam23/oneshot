# Рендер и проверка

## Рендер

```bash
oneshot render comp.html --out draft.mp4 --audio sfx.wav              # черновик: 1920×1080, 30 к/с, размытие до 16 подкадров
oneshot render comp.html --out draft.mp4 --from 40 --to 52            # только кусок — быстро посмотреть правку
oneshot render comp.html --out draft.mp4 --blur 0                     # без размытия — самый быстрый
oneshot render comp.html --final --out final.mp4 --audio mix.wav      # финал: 3840×2160, 60 к/с, до 24 подкадров
```

Как это устроено:

- страница открывается в нескольких Chromium сразу (`--workers`, по умолчанию ядра − 2, не больше 8),
  каждый рендерит свой кусок ролика и отдаёт кадры в свой ffmpeg; куски склеиваются без перекодирования;
- **размытие движения**: внутри «открытого затвора» (половина кадра, `--shutter 0.5`) делается несколько снимков,
  ffmpeg усредняет их (`tmix`). Сколько снимков — решает скорость на экране (`oneshot.motion`): чтобы соседние копии
  стояли не дальше `--gap 10` px; медленный кадр — 2–3 снимка, быстрый — до `--blur` (16 в черновике, 24 в финале),
  неподвижный — один. Так нырок камеры смазывается сплошной полосой, а не лесенкой копий;
- усреднение идёт **в линейном свете** (перевод из гаммы и обратно), как у настоящей камеры: смаз светлого по тёмному не грязнеет
  (`--gamma off` — по-старому, вдвое быстрее: удобно для черновиков, где вы смотрите только тайминг);
- перед стартом рендер запускает `oneshot lint`: с синтаксической ошибкой или съеденным кодом он не начнётся;
- затвор не открывается через объявленную склейку (`F.beat(t, …, { cut: true })`): склейка остаётся резкой;
- рядом с видео пишется `*.render.json`: сколько снимков, неподвижных кадров, секунд.

Ориентиры по времени на 8 потоках: 90 секунд черновика ≈ 2 минуты (≈ 1 минута с `--gamma off`), финал 4K60 ≈ в 6–10 раз дольше.
Если на очень быстром движении видны «ступеньки» — поднимите `--blur 32` или уменьшите `--gap 6`.

## Проверка: `oneshot check comp.html [--video draft.mp4]`

| нога | что проверяет | провал |
|---|---|---|
| переходы | **находит их сама**, без разметки автора: кадр раз в 0,1 с раскладывается на видимые элементы (с учётом обрезки), граница — где заметная часть содержимого исчезла и заметная появилась (окна 0,4 / 0,8 / 1,5 / 2,5 с, неподвижные якоря не считаются). Через границу должно что-то перейти: элемент, который сдвинулся, вырос или сменил форму и **из которого выросло новое**; передача на месте (в том числе цепочкой: печать → фигуры → буквы); или камера (нырок, переброс). Склейки — только объявленные `F.beat(t, …, { cut: true })` | перелистывание: ничего не перешло, или якорь двигается, а новое появилось в другом месте |
| подмены | весь ролик раз в 0,1 с: один элемент гаснет, другой проявляется на его месте (оба полупрозрачны одновременно); тот же текст гаснет в одном элементе и проявляется в другом; **текст перескочил** — в один момент исчезла надпись и появилась другая с теми же словами, даже в другом месте (рендер со смазом покажет обе сразу). Объявленные склейки не считаются | любой наплыв или перескок |
| ритм | длины сцен между `F.beat`: разброс ≥ 0,30, самая длинная / короткая ≥ 3 | разброс < 0,2 |
| однообразие | один и тот же жест (тот же вызов с теми же параметрами) в разные моменты; каскад в пределах 0,6 с — одно использование | больше 20 раз (12–20 — внимание) |
| камера | перепад масштаба, нырки (×2 за 1,5 с), перебросы (больше 0,8 кадра за 0,6 с), доля переездов в одну сторону | — (внимание: «листает», мало нырков и перебросов) |
| мусор | элемент мира без позиции (left/top = 0) с текстом или фоном виден в кадре — его забыли поставить или удалить | любой такой элемент |
| без жизни | элементы, скрытые строгим режимом, потому что у них нет `F.life` | — (внимание: объявите жизнь или удалите) |
| кадр | всё из `F.keep` остаётся в кадре (допуск 2 %) | объект вылетел |
| текст | экранный размер шрифта видимого текста (раз в 0,5 с) | мельче 16 px дольше секунды; 16–22 px — внимание; мельче 9 px не считается: это фактура общего плана |
| страница | ошибки в консоли | любая ошибка |
| код | то же, что `oneshot lint`: синтаксис скриптов, `//`-комментарий, съевший вызов, ссылка на несуществующий `#элемент`, элементы разметки, которые нигде не используются | синтаксис, съеденный код, несуществующий элемент |
| передышки | по видео: доля почти неподвижных кадров ≥ 15 %, самая длинная пауза ≥ 0,8 с | — (только внимание) |
| длина | видео = композиция | — |
| звук | пик ≤ −1 дБ | хрипит |

Итог: **ОК**, **ОК С ЗАМЕЧАНИЯМИ** (объясните замечания человеку) или **ПРОВАЛ** (исправить до показа).
`--json report.json` — сохранить отчёт.

Проверка не заменяет взгляд: перед рендером всегда смотрите `oneshot stills` — пустые кадры, наложения и неудачные
композиции видит только глаз.

## Регрессии: `oneshot snap` и `oneshot lint`

Правка в одной сцене часто ломает другую: элемент без позиции встаёт в угол мира и висит с первой секунды,
перенос времени сдвигает соседнюю сцену. Поэтому:

```bash
oneshot snap comp.html            # перед правкой: эталон — кадр каждые 2 с
# … правка …
oneshot lint comp.html            # за секунду: синтаксис, съеденный код, несуществующие и лишние элементы
oneshot snap comp.html            # после: какие кадры изменились и картинки разницы diff_*.png
oneshot snap comp.html --update   # принять как новый эталон
```

Если изменились кадры там, где вы ничего не трогали, — это регрессия: найдите её до рендера.

## Референс: `oneshot ref clip.mp4`

Разбор ролика, который нравится, в цифрах: доля покоя, самая длинная пауза, склейки и их серии, длины планов, карта энергии
по секундам. Последняя строка — цели для своего ролика. Делайте это до концептов, если есть референс.
